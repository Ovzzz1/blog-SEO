### 2. Pourquoi Python en agence SEO — la logique économique

- **Les exports SEO crashent Excel** : un crawl Screaming Frog complet, un export GSC (>25 000 lignes via UI, 500K+ via API), un fichier Ahrefs ou un log Apache de 30 jours dépassent la capacité d'Excel ou la rendent ingérable. Pandas avale 1M+ lignes sans broncher.

## Details

### 3. Les use cases Python les plus rentables en agence SEO (le 80/20)

Classés par **fréquence × impact** dans une journée de Consultant SEO en agence :

#### 3.1 — Manipulation d'exports tabulaires (le pain quotidien)
- **Lire un crawl Screaming Frog** (`Internal:HTML`, `All Inlinks`, custom extraction) avec `pd.read_csv()` ou `pd.read_excel()`.
- Filtrer les URLs en `noindex`, les title vides, les title >60 caractères, les meta descriptions dupliquées, les pages orphelines, les redirections en chaîne.
- **Croiser plusieurs sources** : GSC + GA4 + crawl + Ahrefs sur la clé "URL" via `pd.merge()` (équivalent VLOOKUP mais sans les bugs Excel sur les gros volumes). C'est la technique du *"data blending"* documentée par Hamlet Batista et reprise dans Search Engine Journal.
- **Comparer deux crawls** (text-only vs JavaScript rendered) pour détecter les pages où Googlebot ne voit pas le contenu — un classique pour les sites JS-heavy (React, Vue, Next.js).

#### 3.2 — Analyse GSC à grande échelle
- L'UI GSC est plafonnée à 1 000 lignes par export. Avec **l'API GSC + Python**, on extrait 25 000 lignes par requête, jusqu'à 500K+ par mois en bouclant sur les dates.
- Use cases concrets : **détection de cannibalisation de mots-clés** (script de référence : `jmelm93/seo_cannibalization_analysis` repris par JC Chouinard), pages "striking distance" (positions 11-20), opportunités de CTR (impressions hautes / CTR bas vs benchmark par position), backup historique dans MySQL/BigQuery.
- Wrapper Python recommandé : **`google-searchconsole`** de Josh Carty (auth simplifiée, retourne des DataFrames pandas directement).

#### 3.3 — Redirect mapping pour migrations
C'est *le* script qui justifie l'apprentissage à lui seul. Approche standard :
1. Crawl du site legacy + crawl du site cible avec Screaming Frog (export `internal_html.csv`).
2. Script Python qui matche les URLs anciennes/nouvelles via fuzzy matching sur le slug, le H1 et le title (souvent trois passes successives).
3. Librairies : **`polyfuzz`** (TF-IDF par défaut, ou modèle SentenceTransformer pour du sémantique) ou **`RapidFuzz`** (Levenshtein rapide).
- Référence agence : le `migration_mapper.py` de Lee Foot (`searchsolved/search-solved-public-seo` sur GitHub), le tutoriel d'Antoine Eripret (`aeripret.com/redirects-at-scale`), et l'approche AI-assistée publiée dans Search Engine Land par Daniel Emery.
- Utile aussi pour **reclasser des 404 historiques** (export Ahrefs + GSC) vers les pages vivantes les plus proches sémantiquement.

#### 3.4 — Analyse de log files (Googlebot)
Données plus fiables que GSC Crawl Stats (qui est échantillonné). On parse un access log Apache/Nginx et on cherche :
- Quelles sections du site Googlebot crawle réellement (% du crawl budget alloué au /blog/, /catégories/, paramètres, etc.).
- Pages crawlées **mais** non indexées (cassure de crawl budget).
- Bots non-Googlebot qui dévorent la bande passante.
- Validation par reverse DNS lookup (librairie `dnspython`) — important parce que les user-agents se spoofent.
- Outil de référence : **`advertools.logs_to_df()`** (Elias Dabbas) qui parse un access log directement en DataFrame parquet, beaucoup plus rapide que d'écrire la regex à la main.

#### 3.5 — Crawl & scraping ciblés
- **Crawl de masse** : `advertools.crawl()` (basé sur Scrapy) ou `screamingfrogseospider` en CLI lancé depuis Python pour automatiser des audits récurrents (ex : crawl nocturne planifié, push vers BigQuery, dashboard Looker Studio).
- **Scraping ponctuel** : `requests` + `BeautifulSoup` pour récupérer un title, un H1, du JSON-LD, ou vérifier la présence d'une balise sur 1 000 URLs.
- **SERP scraping** : passer par une API (SerpApi, ValueSERP, DataForSEO) plutôt que de scraper Google directement (banni rapidement). Le retour structuré (featured snippet, PAA, AI Overview) ne s'obtient pas via GSC.

#### 3.6 — Clustering sémantique de keywords
- Méthode 2024-2026 : **embeddings** (OpenAI `text-embedding-3-small` ou `sentence-transformers/all-MiniLM-L6-v2` en local) + clustering (`hdbscan` ou `KMeans` via scikit-learn) + visualisation (UMAP, plotly).
- Use case concret : sortir d'un export Ahrefs/SEMrush de 50 000 keywords des clusters d'intention de recherche, mapper vers des pages existantes, identifier des trous de cocon sémantique.
- Référence : tutoriel SEJ "How To Automate SEO Keyword Clustering By Search Intent" (Andreas Voniatis) + outil de Lee Foot `SEJ_Semantic_Clustering_Tool_by_LeeFootSEO.ipynb` (Google Colab, prêt à l'emploi).

#### 3.7 — Reporting / dashboards automatisés
- **Pull GA4** : librairie officielle `google-analytics-data` (méthode `runReport` / `batchRunReport`).
- **Pull GSC** : `google-searchconsole` (Josh Carty) ou client `googleapiclient`.
- **Push vers Google Sheets / Looker Studio / BigQuery** : `gspread`, `pandas-gbq`, ou export CSV simple.
- Logique : un cron/Task Scheduler qui fait tourner le script chaque lundi 8h, met à jour un Google Sheet, alimente Looker Studio. Eskimoz le fait à grande échelle via leur App propriétaire ; en tant que consultant junior/médior, savoir le faire pour 1-2 clients est déjà un bel argument.

#### 3.8 — Use cases secondaires mais utiles
- **Génération XML sitemap** dédié aux top pages (filtrer par clics GSC > seuil).
- **Vérification de status codes en bulk** sur une liste d'URLs (`requests.head()` en boucle threadée).
- **Bulk audit de Core Web Vitals** via PageSpeed Insights API.
- **Génération de meta descriptions** ou de titles via OpenAI/Claude API (avec garde-fou : tier deterministe Python pour les checks longueur/duplication, LLM uniquement pour les cas ambigus — pattern documenté dev.to / freecodecamp).
- **Internal linking** par similarité d'embeddings (méthode "BERTlinker" de Lee Foot, ou méthode Indeed via Screaming Frog Custom JS + OpenAI).

### 5. Ce qu'un consultant SEO non-développeur doit absolument comprendre en Python

L'objectif n'est pas de devenir développeur. C'est de **lire un script, le modifier (changer un chemin de fichier, une URL, une période), le faire tourner sans paniquer quand une erreur s'affiche, et savoir demander à ChatGPT/Claude de l'adapter intelligemment**. Le socle minimum :

1. **Variables et types** (`str`, `int`, `float`, `bool`). Comprendre que `"123"` ≠ `123`, et qu'un type wrong entraîne 80% des erreurs débutant.
2. **Listes `[ ]` et dictionnaires `{ }`** : les listes pour des séries (URLs, keywords), les dicts pour des structures clé-valeur (réponses API JSON, config).
3. **Boucles `for`** : `for url in urls:` … parcourir une liste d'URLs et faire une action sur chacune. C'est la moitié des scripts SEO.
4. **Conditions `if / elif / else`** : tester un status code, vérifier qu'un H1 existe, brancher selon le cas.
5. **Fonctions** : `def ma_fonction(arg):` … réutiliser un bloc de code. À comprendre pour relire les scripts d'autres, pas forcément à écrire en partant de zéro.
6. **Imports** : `import pandas as pd`, `from bs4 import BeautifulSoup`. Comprendre la différence entre installer (`pip install pandas`) et importer (`import pandas`).
7. **Lecture/écriture de fichiers tabulaires** : `pd.read_csv('export.csv')`, `df.to_excel('output.xlsx', index=False)`. C'est le pain quotidien.
8. **Manipulations pandas de base** : `df.head()`, `df.shape`, `df['colonne']`, `df[df['Status Code'] == 404]`, `df.merge(autre_df, on='URL', how='left')`, `df.groupby('Type').size()`, `df.drop_duplicates()`.
9. **Appel à une API REST** : `requests.get(url, headers={...})`, vérifier `response.status_code`, parser `response.json()`. Comprendre ce qu'est un token/clé API et un fichier `.env` ou `credentials.json`.
10. **Gestion d'erreurs basique** : `try / except` pour ne pas crasher quand une URL renvoie un timeout sur 1/1000.
11. **Environnements** : utiliser **Google Colab** pour 80% des cas (zéro installation, exécution dans le navigateur, partage immédiat avec un client/collègue), ou Anaconda + Jupyter Notebook + VS Code en local pour les besoins récurrents.
12. **Lecture d'un message d'erreur Python** : `KeyError`, `IndexError`, `ModuleNotFoundError`, `TypeError`. 90% se résolvent en collant l'erreur dans Claude/ChatGPT.

> 💡 **Hack 2026** : avec Claude Code, Cursor ou ChatGPT (mode Code Interpreter), un consultant non-dev peut générer 80% du code dont il a besoin **à condition de savoir formuler la demande avec les bonnes briques mentales** ci-dessus. Savoir ce qu'on demande (et lire ce qui est généré pour repérer une bêtise) > savoir taper le code.

### 6. Top 10 priorisé : les concepts/scripts à maîtriser en premier (ordre de priorité)

**Priorité 1 — pandas + lecture/jointure d'exports CSV (Screaming Frog, GSC, Ahrefs)**
> Couvre 50% des demandes opérationnelles. C'est le multiplicateur de productivité immédiat. Méthodes clés : `read_csv`, `merge`, `groupby`, `query`, `to_excel`. Tutoriel de référence : guide pandas SEO de JC Chouinard + article SEJ "7 Example Projects to Get Started with Python for SEO".

**Priorité 2 — Lancer Google Colab et exécuter un notebook existant**
> Apprendre à : ouvrir un `.ipynb` GitHub dans Colab, monter Google Drive, uploader un CSV, run all cells, lire l'erreur. C'est ce qui te débloque sur 100+ scripts open-source (Lee Foot, JC Chouinard, Greg Bernhardt).

**Priorité 3 — Redirect mapper (polyfuzz / RapidFuzz)**
> Le script qui te rapporte le plus dès la première migration cliente. Référence : `searchsolved/migration_mapper`, ou la version simplifiée d'Antoine Eripret. Apprend à régler le seuil de similarité, à QA manuellement les matchs <90%.

**Priorité 4 — API GSC avec `google-searchconsole`**
> Permet d'extraire toutes les requêtes/pages au-delà du plafond UI. Use cases : cannibalisation, striking distance, monitoring de queries de marque. Tutoriel JC Chouinard "Google Search Console API: Complete Guide".

**Priorité 5 — `requests` + BeautifulSoup pour scraper en bulk un élément précis**
> Vérifier en masse la présence d'un schema, d'un H1, d'un canonical, d'un noindex sur une liste d'URLs (export client). Boucle simple, gestion des timeouts.

**Priorité 6 — `advertools` pour crawl + sitemap + logs**
> Trois fonctions à connaître : `adv.crawl()`, `adv.sitemap_to_df()`, `adv.logs_to_df()`. Une seule ligne de Python pour ce qui demanderait 50 lignes de regex artisanale.

**Priorité 7 — Clustering sémantique de keywords (embeddings + KMeans/HDBSCAN)**
> Aligné avec le pivot GEO d'Eskimoz. Outil prêt à l'emploi : Semantic Clustering Tool de Lee Foot (Colab). Comprendre les concepts : embedding, similarité cosinus, cluster, intention de recherche.

**Priorité 8 — Pull GA4 via l'API + génération d'un Sheet de reporting**
> `google-analytics-data` + `gspread` ou export CSV pour Looker Studio. Cron hebdomadaire, fini le copier-coller du lundi matin.

**Priorité 9 — Analyse de log files (Googlebot)**
> Sur les gros sites Eskimoz (CAC40, e-commerce, médias), c'est un livrable très valorisé. `advertools.logs_to_df()` + `dnspython` pour valider Googlebot. Use case : crawl budget allocation par section.

**Priorité 10 — Wrapping LLM (OpenAI/Claude API) pour audit/rewriting à l'échelle**
> Le terrain GEO d'Eskimoz. Pattern à connaître : tier 1 deterministe Python (longueur, duplication, présence) → tier 2 LLM uniquement pour les cas ambigus. Économise 90% du coût API et garde la qualité.

### 8. Stack tech & contexte des agences SEO françaises (zoom Eskimoz)

**Eskimoz** se distingue par un pôle R&D intégré (Data Scientists + Data Engineers internes) et des **outils propriétaires** :
- **Eskimoz App** : plateforme propriétaire qui centralise SEO, GEO, SEA, Shopping, Brand. Remplace 5-10 licences éparpillées.
- **Predictive Ranking** : outil ML maison qui prédit les facteurs de ranking par requête et priorise les optimisations on-page. Communication marketing : *"90 % des pages optimisées obtiennent des résultats sous 2 semaines"* (claim Eskimoz, à prendre comme une statistique commerciale auto-déclarée — pas de méthodologie publique).
- **Une trentaine de licences** SEMrush, Ahrefs, Screaming Frog, SEObserver, Oncrawl, Majestic.

Pour un consultant junior/médior, **la plupart de la stack lourde Python est encapsulée dans Eskimoz App** : l'attente n'est *pas* d'écrire from scratch un crawler distribué, mais :
1. De **comprendre** ce que fait l'outil propriétaire (pour le pitcher au client).
2. De **scripter à la marge** : adapter un template, automatiser une tâche récurrente du portefeuille, croiser deux exports.
3. De **collaborer avec le pôle Data** : savoir poser des spécifications correctes (ex : "j'ai besoin d'un dump GSC par URL sur 12 mois avec dimension device").

## Caveats

- **L'offre WTTJ Eskimoz n'a pas pu être fetchée directement** (URL bloquée par les permissions de l'outil) ; les éléments précis cités sur la stack et le process viennent des résultats de recherche Google qui retournaient le contenu indexé de la page (mêmes phrases en clair). Le contenu cité est cohérent entre plusieurs requêtes mais doit être recoupé avec l'offre live au moment de postuler — les annonces évoluent.
- **"Premières compétences en Python ou en automation"** est une formulation **soft** (côté "Profil recherché", pas "Exigences"). Concrètement, tu peux passer le process avec uniquement Make/n8n + de la curiosité Python. Mais les profils qui ressortent dans les comités de recrutement Eskimoz sont ceux qui peuvent **démontrer** au moins 1-2 mini-projets Python concrets sur le cas pratique technique.
- Les claims commerciaux d'Eskimoz (*"90% des pages optimisées avec Predictive Ranking obtiennent des résultats sous 2 semaines"*, *"35M€ de CA"*, *"250+ collaborateurs"*) viennent de leur communication corporate (site, fiches WTTJ, articles partenaires comme Page1.fr, Oscar Black). Aucune source indépendante ne les vérifie ; à interpréter comme des éléments de marque employeur, pas des données auditées.
- L'écosystème Python-for-SEO bouge vite : `pyGTrends` est largement obsolète, `searchconsole` (la vieille lib) a été remplacée par `google-searchconsole` de Josh Carty, et certains tutoriels d'avant 2022 référencent l'API Universal Analytics qui ne fonctionne plus (migration GA4). Privilégier les ressources 2023-2026.
- **Hamlet Batista est décédé en janvier 2021** (COVID). Son corpus reste fondamental mais "legacy" — le mouvement a été repris par JC Chouinard, Lee Foot, Elias Dabbas, Andreas Voniatis et l'initiative `seopythonistas.com`.
- **Attention au scraping de Google directement** : les ToS l'interdisent et les protections anti-bot bloquent rapidement. En agence, on passe systématiquement par une API tierce (SerpApi, ValueSERP, DataForSEO) ou par GSC pour les données propriétaires.
- Les exemples de code dans ce guide sont volontairement omis : l'objectif est la **carte mentale du 80/20**, pas un cookbook. Pour le code, suivre les liens repos GitHub cités (Lee Foot, advertools, JC Chouinard, etc.) qui ont l'avantage d'être maintenus à jour.
- La distinction **Python "vrai" vs Python "via LLM"** n'a jamais été aussi floue qu'en 2026 : un consultant SEO non-dev équipé de Claude Code/Cursor peut produire des scripts qu'il ne saurait pas écrire de tête. Cela rend les bases (priorités 1-2 ci-dessus) **plus** importantes, pas moins, parce qu'il faut savoir relire et valider le code généré pour ne pas pousser un redirect mapping bidon en production.
